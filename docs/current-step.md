## Проверяемая реализация

Программа читает `MAPS/*.MAP`, `TERRAIN/*.MCD`, `GEODATA/LOFTEMPS.DAT` из локального каталога игры. MAP имеет трёхбайтовый заголовок (X/Y/Z) и четыре байта на ячейку; проверяется ровно `3 + 4×X×Y×Z`. MCD — целое число записей по 62 байта; LOFTEMPS — целое число 32-байтовых блоков.

Отчёт — JSON `fgm-regenerator/inspection-v1`. По умолчанию данные пишутся в stdout, необязательный файл отчёта располагается **вне** источника игры. Абсолютные пути, содержимое MAP/MCD/LOFTEMPS, исходные спрайты и файлы сохранений не попадают в JSON.

**Важно:** размерные проверки ещё не подтверждают смысл полей и не гарантируют согласованности карт, маршрутов и вокселей.

## Правила завершения задачи и передачи контекста

Каждый PR обязан содержать проверяемые дочерние Requirements с отношениями `derives_from`, `implemented_by` и `verified_by` для реализованных свойств. Тесты — на собственных синтетических данных, исходные коммерческие файлы не коммитить.

Для продолжения в новом чате читать в порядке: этот документ → [R12 #17](https://github.com/netkeep80/fgm-regenerator/issues/17) → [эпик R00 #4](https://github.com/netkeep80/fgm-regenerator/issues/4) → `requirements/` → текущий Draft PR и его exact SHA.

Перед закрытием среза в Issue фиксируются **BASE, HEAD, TREE, CI, тесты, статус принятия, merge-коммит и следующий один шаг**. `main` не изменять напрямую. Merge без явного авторского принятия запрещён.
